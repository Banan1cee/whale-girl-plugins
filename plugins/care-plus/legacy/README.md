# care-plus · 主动搭话增强（v0.7.1）

替换官方 care 的「定时问候」，但**不改主程序一行代码**。插件只做两件事：决定什么时候开口、决定说什么。

## 效果

一句话：**丰富主动搭话时的提示词和时间随机性，降低人机感。**

| | 官方 care | 装上本插件 |
|---|---|---|
| 说什么 | 固定 6 行独立提示词，只有最近 8 条原文，四条搭话一个语域 | 完整人设 + 人物卡里未收尾的话题/事实/事件 + 她自己日记的末段，每轮的话头都不一样 |
| 什么时候说 | 90 ± 25 分钟稳定抖动，锚点是「上次搭话时间」，刚聊完也会按点再来一句 | 每次真随机（默认 25~300 分钟，群聊再 ×1.6），锚点是「你最后一条消息的沉默时长」 |
| 被无视之后 | 完全无感知，继续按点问候 | 记次数，进提示词改语气（第二次起主动砍掉提问角度），连续 3 次停手 |

所以实际体感是：不会刚聊完又冒一句、不会每天固定几个点出现、不会连着几条都是「吃饭了吗」，语气和长度也跟着她当时的状态变——**「到点就发」的痕迹基本消失**。

## 它解决什么

官方 care 的实测表现（同一台机器，一天四条）：

```
01:09  这会儿真躺下了没，还醒着的话别硬扛
10:00  早，昨晚睡得还行吗，今天忙不忙？
12:07  中午吃了吗，别又忙得忘了
19:30  这么晚还在忙吗，早点休息
```

四条全落在同一个语域（问候 / 问吃没吃 / 问累不累）。根因不在模型：

| 问题 | 官方 care | 本插件 |
|---|---|---|
| 计时锚点 | 上次**搭话**时间（所以刚聊完也会按点再来一句） | 你最后一条消息的**沉默时长** |
| 间隔 | 90 ± 25，稳定抖动，可预测 | 每次真随机 25~300 分钟 |
| 未回复 | 完全无感知 | 记次数，进提示词改语气，连续 3 次直接停手 |
| 提示词 | 独立 6 行，跟人设脱钩 | 复用官方 `/api/debug/prompt` 的完整 system |
| 上下文 | 最近 8 条原文，且「别复述」 | 人物卡的 open threads / 事实 / 事件 + 她自己日记的末段 |
| 群聊 | 与私聊同一份提示词 | 不主动进群（保守） |

## 装之前

- 鲸鲸 **4.1.2 或以上**（本机 4.1.7，已核对 `/api/plugins/capabilities` 返回 `api:4`）
- 设置里打开「启用 JavaScript 插件（实验性）」总闸
- 插件声明 `system.full`，也就是把它当本机程序信任——它确实能读写你的文件和调用全部 API

## 安装

1. 插件市场 → 从本地安装 → 选 `dist/care-plus-0.1.0.zip`
2. 在「已安装」找到「主动搭话增强」，确认权限，**启用**
3. 卡片「设置 → 运行一次」，输入 `{}` 或 `{"count":5}` — 只生成，**不发任何消息**
4. 满意之后再决定要不要接管定时

## 发给谁

完全按官方白名单走，不额外维护名单：

| 官方配置 | 插件怎么用 |
|---|---|
| `care.whitelist` | 收件人集合，群和私聊都在里面 |
| `care.onlyMaster` / `allowOthers` / `allowGroups` | 逐个过滤，和官方判定一致 |
| `group.mutedGroups` | 静音会话一律跳过，支持 `*` 一把全静音，也认群名 |

文件传输助手不主动找。主人排最前，其次是别人的私聊，最后才是群。

**每个会话各自计时**：谁安静得最久先找谁，一次检查只发一条，避免几个会话同时刷屏。

### 群聊怎么搭话（参考 astrbot 那份插件的做法）

| 私聊 | 群聊 |
|---|---|
| 锚点：对方沉默多久 | 锚点：**群里**多久没人说话 |
| 间隔：官方 every±jitter | 间隔：再乘 1.6、下限 45 分钟（群更克制） |
| 每天：官方 `maxPerDay` | 每天最多 **2** 条 |
| 连续 3 次没回停手 | 连续 **2** 次没人接就停 |
| 素材：人物卡 + 她的日记 | 素材：**只**用群里最近 8 条，绝不掺私聊内容和日记 |
| 目标：接住上一句 | 目标：起个**多人都能接**的话头，不 @ 任何人、不点名 |

群聊提示词里明说「你不是在回复谁」「不要点名」「不要提只有你和某个人才知道的事」，避免把私聊的事说到群里。

## 给所有人用

这不是给某一台机器写的插件。所有个人化的东西都在运行时从配置读，代码里没有写死的人名、wxid 或路径：

| 会不会写死 | 实际做法 |
|---|---|
| 她叫什么 | `persona.name` + `aliases`；输出里「名字：」前缀也按这份名单剥 |
| 发给谁 | 默认只发主人 `persona.master.wxids[0]`；主人没绑且官方 `onlyMaster:false` 时，退回官方白名单里第一个**私聊**。群和文件传输助手永不主动找 |
| 什么时候发 | 官方 `care.windows / everyMinutes / jitterMinutes / maxPerDay / quietAfterMinutes` |
| 记忆在哪 | 按官方规则 `memory/chats/sha1(chatId)[:16]/…` 推；读不到就降级，不报错 |
| 人设从哪来 | 优先 `/api/debug/prompt` 拿官方完整 system，拿不到退回 `config.persona` 拼简版 |

**不留坑：**

- 官方 care 是插件自己关的；停用插件时 `app.stop` 会还回去（只还原自己关的那次，别人本来关着的不动）。
- 读不到会话流水时，不套「连续未回就停手」，退化成纯定时，不会永久沉默。
- 连续 3 次生成失败会主动交还官方 care。
- 只写自己的 `data/plugins/care-plus.data/`。

**唯一会冲突的对象**：另一个也会主动发消息的插件。两个都在跑就各发一份，插件之间无法互相感知。官方 care 已被接管，不存在双发。

## 装完就是终态

**没有需要你设置的东西。** 参数全部读官方「主动与提醒」页；插件一被启用就把官方 care 关掉，由自己接管。

```
第 1 步  安装 → 启用          → 自动关掉官方 care，参数同步官方设定
第 2 步  运行一次 {"action":"status"}   → 看 settingsText 确认读到哪些参数
第 3 步  什么都不用做         → timer.tick 每 5 分钟检查，到点才开口
```

想临时退回官方 care 做对比：`{"action":"restore"}`（会把官方打开并停止自动接管）；想交回来：`{"action":"takeover"}`。

## 设置在哪改

去官方「主动与提醒」页改，插件跟着变：

| 官方那一项 | 插件怎么用 |
|---|---|
| 允许的时间段 `windows` | 直接作为「可以开口的时段」，支持多段、跨零点 |
| 平均间隔 `everyMinutes` + 间隔浮动 `jitterMinutes` | 合成沉默区间：90±25 → 你安静满 65~115 分钟后才可能开口，每次在这个区间里真随机 |
| 最近聊过就不打扰 `quietAfterMinutes` | 并进最短沉默时长，保证刚聊完不会马上冒出来 |
| 每天最多 `maxPerDay` | 每天上限，0 = 不限 |
| —— | 插件额外内置：连续 3 次没回就停手、启动先静默 30 分钟、一次生成 3 条候选、单句 ≤60 字、日记和人物卡都可用 |

插件自己的设置框**留空即可**，不用填任何东西。写了中文键也能生效（`{"间隔":"30-240"}`），属于应急覆盖，正常别用。

核对有没有读到：运行 `{"action":"status"}`，看 `settingsText` 那一行，例如：

```
允许时段 10:00~23:59、00:00~02:00・沉默 65~115 分钟后可能开口・每天不限次数・
连续 3 次没回就停・候选 3 条・单句不超过 60 字・启动先静默 30 分钟・提问开・日记开・人物卡开
```

## 它碰了什么，没碰什么

**只读**：`data/config.json`、`data/contacts-cache.json`、`data/memory/chats/<hash>/messages.jsonl`、同目录 `people/<hash>.json`。

**只写**：自己的 `state`（宿主托管，64 KiB）和通过官方接口发送。发送成功后调 `POST /api/care/sent` 把那句写回她的上下文——否则你回过来时她不知道自己刚说过什么，这是官方 care 早先踩过的坑。

**唯一会改配置**：`{"action":"takeover"}` 会把 `care.enabled` 设为 false。不做这一步，两个链路会同时发。

**绝不**：进群、发给非主人、伪造入站消息、写主程序文件。

## 已知限制

- `/api/debug/prompt` 不是稳定契约。拿不到人设时会退回用 `config.persona` 拼的简版（`promptSource: 'fallback'`），效果明显变差但不会崩。
- `timer.tick` 在电脑休眠 / 内核停止期间不执行、**不补跑**。醒来不会补发一串。
- `sendText` 返回 `queued` 不等于微信已送达。所以「有没有被回」一律以流水里有没有新的 user 消息为准，不看队列状态。
- 目前只服务 `config.persona.master.wxids[0]` 这一个私聊。
- 判定与生成时都读流水，读失败一律当「没有历史」处理，宁可这轮不发。

## 文件

```
plugin.json          清单（Api 4 / Kind tool / 4 个钩子 / system.full）
plugin.js            全部逻辑，约 1300 行，零第三方依赖
dist/care-plus-0.7.1.zip   可安装包（根目录仅 plugin.json + plugin.js）
dev/test.js          纯逻辑自测（30 项，不联网）
dev/takeover-test.js 接管官方 care 的自测（打桩，不改真实配置）
dev/fallback-test.js 生成连续失败时交还官方的自测
dev/rename-name.js   把记忆里的旧名字成批换掉（干跑 / --write）
dev/run.js           真模型试跑，不发送
dev/tick.js          端到端跑一次 timer.tick，发送打桩
```

试跑输出示例（同一个会话，连续两次没被回）：

```
连续第 1 次没被回  →  <接着上次没说完的事问一句>
连续第 2 次没被回  →  <只说她自己的事，不再提问>
```

第二次会自动砍掉提问角度，只说自己的事——「被冷落之后还追问」是最劝退的。

开发命令：

```bash
node dev/test.js          # 18 项断言
node dev/run.js 3         # 生成 3 个候选看看
node dev/run.js --status  # 看判定与状态
node dev/tick.js 1        # 模拟一次到点发送（不会真的发）
```

## 更新记录

**0.7.1**

- **修致命 bug**：0.7.0 重构时把 `sendNow()` 的定义删掉了，只剩调用 → 每次发送都抛 `sendNow is not defined`，插件 3 次失败后把话筒交还官方，导致 11:20 那条其实是官方 care 发的。已补回并加了本地发送冒烟测试。
- 降级门槛放宽：从「3 次失败」改成「连续 4 次且横跨 20 分钟以上」——一次 503 不应该把接管权交出去。
- 因生成失败而交还官方后，新版本启动会自动恢复接管（手动 `restore` 的暂停保持不变）。
- 自测 32 项 + 接管 5 项 + 降级 2 项 + 发送冒烟 1 项。

**0.7.0**

- 支持**群聊**与**非主人私聊**：收件人完全读官方 `care.whitelist`，按 `onlyMaster / allowOthers / allowGroups` 过滤，`group.mutedGroups` 里的会话（含 `*` 通配、群名）直接跳过。
- 状态从「单会话」改成「一会话一格」，各自计时；一次 tick 只发一条，按谁安静最久优先。
- 群聊独立策略：间隔 ×1.6、下限 45 分钟、每天最多 2 条、连续 2 次没人接就停；提示词只喂群内最近 8 条，禁提私聊与日记。
- 别人的私聊只用那个人自己的人物卡，**不用她的日记**（避免把主人的事说给旁人）。
- `status` 会列出所有收件人和各自状态；试跑支持 `{"mode":"group"}` 或 `{"target":"wxid"}`。
- 自测 32 项（含白名单/静音/权限矩阵）。

**0.6.1**

- 过滤「调试类话题」当话头：含「语音/消息/回执/引用/截图/插件/接口…」+「收到/接收/是否/确认/生效」的条目跳过。这类话题本来就是主人在测功能，模型拿到必然写成「我刚发了语音」。
- 提示词补一条：不许说「发了语音 / 发了图片 / 收到了什么」，只能打字。
- 自测 33 项。

**0.6.0**

- **去个人化**：删掉最后几处写死人名的地方（输出清洗的「名字：」前缀、无配置时的默认名）。名字一律从 `persona.name` / `aliases` 算。
- 发送目标修正为 `wxid`（之前传的是复合会话键 `wechat:u:<wxid>`，靠显示名兜住才发成功，换个人可能失败）。
- 主人没绑时，按官方语义退回白名单里的私聊（仅在官方 `onlyMaster:false` 时），绝不进群、不找文件传输助手。
- `app.stop` 会把「自己关掉的官方 care」还原回去，停用插件不留空洞。
- 读不到会话流水时不再累加未回复计数，避免在其他存储布局上「发 3 次就永久沉默」。
- `status` 的 `master` 字段改名 `target`，多一个 `kind`（master / whitelist）。
- 开发脚本支持 `WHALE_APP` / `WHALE_DATA` 环境变量，不再绑死某台机器。
- 自测 32 项。

## 已知问题（下一版处理）

- 模型偶尔会自己编日期：实测出现过「你早上是周三还是周四让学生做分享」这种把已知事实说岔的提问。话头里的事实是对的，是模型自由发挥时加的。后续可以给「不确定的具体事实」加白名单校验，或者干脆禁止在问句里引入新日期。
